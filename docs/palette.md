# Lunaria — Palette Design

> **Navigation**: [palette-eink.md](palette-eink.md) covers the E-Ink palette's physical design in detail. [vscode.md](vscode.md) covers how these palettes are applied to VS Code UI chrome.

## Overview

Lunaria is a family of moderate-contrast color palettes for terminals, text editors, and technical documentation. All palettes are built on the **CAM16 color appearance model** and its associated uniform color space (CAM16-UCS) and chromatic adaptation transform (CAT16).

| Palette | Type | Background | Optimized for |
|---------|------|-----------|---------------|
| **Light** | `light` | Light (`#EEE`) | Bright window-lit offices — best facsimile of ink-on-paper on LCD |
| **Dark** | `dark` | Dark (`#1A1A1A`) | Nighttime viewing under dim, warm LED illumination |
| **Eclipse** | `dark` | Darker (`#111`) | Same bright conditions as Light — compensates for increased viewing flare |
| **E-Ink** | `light` | Paper (`#EEE`) | Reflective e-ink displays (B&W and color) — hand-tuned for physical reflectance |

Light, Dark, and Eclipse are algorithmically generated by [`lunaria.ipynb`](../lunaria.ipynb). E-Ink is hand-tuned, informed by CAM16 physical modeling — see [palette-eink.md](palette-eink.md) for the rationale.

## Hue System

### 7 Hues, Skipping Cyan

The human eye's hue discrimination is worst in the cyan region (the "pit of despair" between S and M cone responses). Lunaria uses **6 working hues** spaced approximately 60° apart on the CAM16 hue wheel, deliberately skipping cyan:

| Hue | Angle | Token suffix |
|-----|-------|-------------|
| Red | ~20° | `*Red` |
| Yellow | ~80° | `*Yellow` |
| Green | ~140° | `*Green` |
| Blue | ~260° | `*Blue` |
| Violet | ~300° | `*Violet` |
| Magenta | ~340° | `*Magenta` |

Blue and Violet fill the 120° gap left by cyan, providing better perceptual separation than a forced cyan inclusion would.

## Contrast Tiers

Every hue exists in three contrast levels, forming the backbone of Lunaria's color vocabulary:

| Tier | Prefix | Purpose | Lightness relationship |
|------|--------|---------|----------------------|
| **High Contrast** | `hc*` | Navigation, critical elements, visually-impaired fallback | As dark/light as `fg` — maximum readability |
| **Vivid** | `vivid*` | Emphasis, status, errors, warnings | Cool/warm asymmetry — cool tones darker, carrying cultural associations (red/yellow → error/warning) |
| **Soft** | `soft*` | Body text, syntax highlighting, secondary elements | Same lightness as `mediumGray` — fungible, devoid of individual psychological associations |

### Cool/Warm Asymmetry (vivid tier)

In the vivid tier, cool hues (blue, violet, green) are darker than warm hues (red, yellow, magenta). This reflects natural perceptual expectations — cool colors recede, warm colors advance — and ensures vivid colors carry distinct psychological associations without relying on hue alone.

## Neutral Scale

Lunaria's grayscale is derived from physical spectral measurements. The Dark palette's neutrals are based on actual data collected from the Fred Lawrence Whipple mountaintop astronomical observatory.

| Token | Role |
|-------|------|
| `deepBlack` | Deepest possible background |
| `black` | Black point |
| `darkGray` | Dark neutral |
| `mediumGray` | Mid-tone — reference lightness for `soft*` colors |
| `lightGray` | Light neutral |
| `white` | White point |
| `brightWhite` | Brightest white |

Foreground/background context tokens:

| Token | Role |
|-------|------|
| `fg` | Default foreground (text) |
| `emphFg` | Emphasized foreground |
| `deEmphFg` | De-emphasized foreground (comments, secondary text) |
| `bg` | Default background |
| `emphBg` | Emphasized background (widgets, hover states) |
| `deEmphBg` | De-emphasized background |

## Background Color Series (bg\*)

Four cardinal **opponent-process hues** (yellow/blue, red/green) provide background washes for diff views, git status, and search highlights:

| Token | Hue | Typical use |
|-------|-----|------------|
| `bgRed` | Red | Diff delete, git removed |
| `bgGreen` | Green | Diff insert, git added |
| `bgBlue` | Blue | Diff modify, git modified |
| `bgYellow` | Yellow | Search match highlight |
| `bgHighlight` | Varies by palette | Find/match highlight |
| `bgLowlight` | Varies by palette | Inactive selection |

## Inverse Tokens

Every color has an `inv*` counterpart designed for use on inverted (dark) backgrounds. These preserve the perceptual identity of the original color when placed on a dark surface — for example, `vividViolet` on a light background becomes `invVividViolet` on the Activity Bar's dark background.

---

## Terminal Colors (termLow\*/termHigh\*)

Lunaria includes a full ANSI 16-color set mapped into its luminance range via log-luminance linear interpolation. `termLow*` replaces the classic ANSI dim colors; `termHigh*` replaces the bright variants.

**ANSI mapping note**: Lunaria Violet maps to ANSI Blue, and Lunaria Blue maps to ANSI Cyan. This satisfies the de facto convention that ANSI Blue should be readable (traditional Blue is too dark on dark backgrounds) while ANSI Cyan provides a distinct cool accent.

---

## Status Bar Color Anchor

`vividViolet` serves as the **single saturated background** in the entire palette system. The Status Bar uses it as a visual anchor — the one element that always carries saturated color. State changes are communicated through hue shifts (violet → green for debugging, violet → yellow for no-folder).

---

## Contrast Philosophy

Lunaria targets **moderate contrast** (7:1–9:1 for body text), deliberately avoiding both:
- High-contrast themes (14:1+) that cause eye strain over long sessions
- Sub-WCAG-AA contrast that impairs readability

The goal is a palette that feels comfortable for 8+ hour daily use while remaining accessible.
